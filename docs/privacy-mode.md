# 隐私保护模式 · 设计方案

> **状态：已实现（P0 + P1 + P2 全做）。** 下方记录了设计取舍与实测结果。
> 依据：对 `core/fragcore.py` / `core/fragserver.py` 的代码审计 + 本机实测（2026-10-12）。
>
> **2026-10-12 更新：加密 DNS 已内置。** 隐私模式现在会**默认自动接管系统 DNS**，
> 把明文查询经本地 DoH 存根转成 HTTPS 发往阿里/腾讯 DoH —— 见 §4.6。
> 这把原本「藏不住」的明文 DNS 变成了「可解决」（§3 的判定已相应更新）。

---

## 0. 结论速览

**能加，而且改动不大。** 但它的价值定位需要先说清楚：

- 这不是一个"新功能"，而是**修正 `global` 模式的语义缺口**。
  现在的全局模式虽然对所有 TLS 分片，却**照样解析并记下域名**，所以它不是隐私模式。
- 真正的增量是四件事：**不解析不记录域名**、**切点随机化**、**端口集扩展**、**本地痕迹最小化**。
- 它**只能藏 SNI**，藏不了明文 DNS、目的 IP、服务器证书、TLS 指纹。
  单独开隐私模式只有"半个隐私"。

一句话方案：新增第 4 种 `mode = privacy`。

| | `off` | `rules` | `global`（现状） | `privacy`（新） |
|---|---|---|---|---|
| 分片范围 | 无 | 命中规则的域名 | 所有 TLS | 所有 TLS |
| 是否解析 SNI | 否 | 是 | 是 | **是（但只为定切点，结果不外泄）** |
| 事件日志里的域名 | — | **完整域名** | **完整域名** | **完全不含** |
| `stats.last_domain` | — | 域名 | 域名 | **恒为 `None`** |
| 切点 | — | 固定偏移 | 固定偏移 | **窗口内随机（可选）** |
| 端口 | 443 | 443 | 443 | **可配集合** |
| `fragconfig.json` 残痕 | 规则 | 规则 | 规则 | 规则（本来就不含域名） |

## 1. 威胁模型：先定义"隐私"防谁

不定义清楚，这个功能会变成一锅粥。

**防的是**：链路上的**上网行为管理设备** —— 只检查连接的第一个 TCP 报文、不做 TCP 流重组、
按 SNI 关键词匹配封禁，并且（合理推测）会记录终端访问了哪些域名用于审计。

**保护的信息**：使用者访问了哪些域名。

**不在范围内**：
- 上游运营商、目标服务器本身
- 本机被他人物理接触（那是磁盘加密的事）
- 具备「流重组 + JA3 指纹 + IP 归属库」的完整 DPI 体系 —— 见 §6.3

## 2. 现状审计（读代码 + 实测）

### 2.1 磁盘上其实没有域名泄露 ✅

落盘点只有一处：`fragserver.py` 的 `save_config()`，由 `Console.persist()` 调用，
只写入 `{"ruleset": …, "params": …}`。
`ruleset` 里是用户配置的规则（域名后缀、关键词）和命中计数 `hits`，**不是被访问的域名**。

所以 `core/fragconfig.json`（当前尚未生成）暴露的是"这台机器装了规避工具、主要在玩哪些游戏"，
不是"访问过什么网站"。这是**工具痕迹**问题，不是访问记录问题。

### 2.2 但内存里有，而且会显示在网页上 ⚠️

```
Engine._loop()  →  on_event("split", res["info"])
                →  Console.log()        # 写进 self.events（deque maxlen=500）
                →  GET /api/events      # 原样吐给浏览器
```

`res["info"]` 的构造（`fragcore.py`）是：

```python
out["info"] = (f"{domain or '未知域名'}  首段 {cut}B{seg_note}"
               f"  命中规则：{rule_name}")
```

**完整域名**。另外 `Engine.stats["last_domain"]` 也存域名，经 `/api/state` 返回。

### 2.3 ⭐ 实测：`global` 模式并不保护隐私

用 `tests/test_fragcore.py` 的构造器造一个完整 IPv4 包，域名取一个**不在任何规则里**的
`www.some-private-site.com`，跑三种模式：

| mode | 是否分片 | 事件日志文本 |
|---|---|---|
| `off` | 否 | （无） |
| `rules` | **否** | （无）→ **设备看到完整 SNI，既能封也能记录** |
| `global` | 是 | `'www.some-private-site.com  首段 220B  命中规则：全局模式'` |

两个结论：

1. **规则模式下非游戏域名完全裸奔。** 这个工具目前只保护它列进规则的域名，
   其余所有 HTTPS 流量都在设备眼皮底下。
2. **全局模式照样把域名写进日志。** 开了全局模式，行为管理设备是看不到了，
   但**工具自己变成了记录器** —— 域名进了内存队列、进了网页、进了 `last_domain`。

第 2 条就是要修的核心缺口。

### 2.4 只覆盖一个端口 ⚠️

`Engine.start()`：

```python
flt = f"outbound and tcp and tcp.DstPort == {self.params.port}"
```

默认 443。8443 / 2053 / 2083 / 2087 / 2096 等备用 TLS 端口**完全不处理**。
浏览器和客户端在部分网络下会自动降级到这些端口。

### 2.5 切点是确定性的 ⚠️

```python
cut = max(params.min_cut, pos - params.guard)     # guard 默认 6
```

每个连接都在**同一偏移**附近切开。这本身就是一个**稳定的可识别签名**：
"这台机器的首段永远在 124B 左右被切断"。

### 2.6 DNS 完全在分片覆盖之外 ⚠️

本机 DNS 是 `192.168.31.1`（路由器），明文 UDP 53，再由路由器转发给上游。
**首包分片管不到 DNS。** SNI 藏得再好，域名照样从 DNS 查询里明文泄露。

## 3. 泄露面与可解性

```
本机 ──[出站 TLS，带明文 SNI]──> 行为管理设备 ──> 目标服务器
```

| 泄露通道 | 隐私模式 | 说明 |
|---|---|---|
| TLS SNI（明文域名） | 🟢 可解决 | 首包分片，设备读不到完整 SNI |
| 明文 DNS 查询（UDP 53） | 🟢 可解决 | **隐私模式默认自动接管**：本地 DoH 存根（§4.6）把查询转成 HTTPS |
| 本机 `fragconfig.json` | 🟢 可解决 | 本来就不含域名；关闭时自动清日志 |
| 目的 IP 地址 | 🔴 治不了 | 分片不改变 IP 头，设备可按 IP 库分类 |
| 服务器证书（TLS 1.2 明文） | 🔴 治不了 | TLS 1.2 的 Certificate 消息是明文，协议层问题 |
| TLS 指纹（JA3 / 扩展顺序） | 🔴 治不了 | 只改分段方式，ClientHello 内容逐字节未变 |

> 注意「明文 DNS」这一行从「需另配」变成了「可解决」—— 这是本次新加的
> `tools/doh_stub.py` 带来的能力，也是隐私模式能被称为"完整"的原因。

## 4. 方案设计

### 4.1 新增 `mode = privacy`

`RuleSet` 的白名单从 `("off", "rules", "global")` 扩为 `("off", "rules", "global", "privacy")`。

`decide()` 里加一条**放在最前**的分支（在 `off` 之后）：

```python
if self.mode == "privacy":
    return (True, "隐私模式")
```

关键点：**不遍历规则**。这样既省 CPU，也保证不会因为某个规则的 `hits` 计数
间接暴露"用户访问了哪一类站点"。

### 4.2 逐个文件的改动点

**`core/fragcore.py`**

1. `RuleSet.TYPES` / `__init__`：mode 白名单加 `privacy`。
2. `RuleSet.decide()`：加 privacy 分支（见上）。
3. `Params`：新增
   - `random_cut: bool = False`（见 §4.4，默认关）
   - `port` 支持多端口（逗号分隔字符串或 list，见 §4.5）
4. 新增内部函数 `_cut_point(host_start, params)`：
   ```python
   lo = max(params.min_cut, MEASURED_DEVICE_THRESHOLD)   # 默认 max(124,114)=124
   if host_start and host_start - 1 >= lo:
       if params.random_cut:
           return random.randint(lo, host_start - 1)
       return max(params.min_cut, host_start - params.guard)
   return max(params.min_cut, (host_start - params.guard) if host_start else params.min_cut)
   ```
5. `split_packet()`：privacy 模式下
   - 仍然调用 `parse_sni()` 拿 `host_start`（**不解析就不知道切哪**），
     但结果只在函数内部存活；
   - `out["domain"] = None`；
   - `out["info"] = f"TLS 分片 · 首段 {cut}B（域名已隐去）"`。
6. `Engine.start()`：filter 支持多端口。
   ```python
   ports = self.params.port if isinstance(self.params.port, (list, tuple)) else [self.params.port]
   expr = " or ".join(f"tcp.DstPort == {int(p)}" for p in ports)
   flt = f"outbound and tcp and ({expr})"
   ```
7. `Engine._loop()`：privacy 模式下**不写** `stats["last_domain"]`。

**`core/fragserver.py`**

1. `/api/mode` 的白名单加 `privacy`；模式中文名映射加一项。
2. `Console.log()` 加一道**兜底脱敏**——防止将来别处又把域名漏进 `text`：
   ```python
   DOMAIN_RE = re.compile(r"\b(?:[a-z0-9-]+\.)+[a-z]{2,}\b", re.I)
   def log(self, level, text):
       if self.ruleset.mode == "privacy" and level == "split":
           text = DOMAIN_RE.sub("<域名>", text)
       ...
   ```
   双保险：`split_packet` 层面已经不含域名，这里是"就算漏了也挡住"。
3. `snapshot()`：privacy 模式下 `last_domain` 强制返回 `None`。
4. 新增 `/api/privacy`（get / set：`random_cut`、`ports`、`clear_on_exit`）。
5. `main()` 的 `finally` 里：privacy 模式且 `clear_on_exit` 时 `CONSOLE.events.clear()`。

**`core/console.html`**

- 模式选择器加第 4 个按钮「隐私模式」。
- 新增「隐私」设置区：随机切点开关、端口集输入、退出时清空日志开关。
- 事件面板在 privacy 模式下显示提示条：「域名已隐去，日志不含访问记录」。

**`tests/test_fragcore.py`** 新增用例（见 §8）。

**`README.md`** 新增一节「隐私保护模式」，**把 §3 那张"能解决什么 / 解决不了什么"的表原样放进去**。

### 4.3 为什么必须保留 `parse_sni`

有个直觉上的误解：既然是隐私模式，那就别解析域名了。

**不行。** 切点位置依赖 `host_start` —— 切割点必须落在 SNI 扩展内部（域名之前），
否则域名会完整落在首段里，分片就白做了。
所以 `parse_sni` 必须调用，**只是它的输出不进入任何日志、统计或返回值**。

### 4.4 随机切点的硬约束（关键，别跳过）

两个边界条件都来自实测：

- **下界**：`cut ≤ 113` 被 RST，`≥ 114` 通过 → `cut ≥ 114`
- **上界**：切点必须落在域名之前，否则完整域名出现在首段 → `cut ≤ host_start - 1`

所以随机窗口是 `[max(min_cut, 114), host_start - 1]`，用默认 `min_cut=124` 就是 `[124, host_start-1]`。

**非空条件**：`host_start - 1 ≥ max(min_cut, 114)`，即 `host_start ≥ 125`。
典型 ClientHello 的域名起始位置在 130~200 之间，窗口宽 6~76 字节，够用。
但极简 ClientHello（扩展少、无 padding）可能 `host_start < 125` → 窗口为空 →
**必须回退固定切点**，并记一条 `warn`。

> ⚠️ **实施前必须先做的验证**：现有实测只证明了"≥114 通过"这一个**边界点**，
> 并没有验证 `[114, host_start-1]` 区间**每一个值**都能通过。
> 如果设备的行为在窗口内不是单调的（例如某些长度触发攒包复检），
> 随机切点会**随机地失败**，而且很难复现。
>
> **所以：随机切点默认关闭。** 开启前先跑一次全窗口扫描
> （改 `tools/sweep_cut.py` 或新写一个脚本，逐个 cut 值验证），确认窗口内全部通过。
> 这一条是这个方案里风险最高的假设，不要跳过。

### 4.5 端口集

- 默认值：`[443]`（保持现有行为，不引入意外）
- 建议可选加入：`8443, 2053, 2083, 2087, 2096, 9443`
- 不建议无脑开"全部端口"：WinDivert filter 越宽，拦截循环处理的无用包越多，
  且非 TLS 流量被误判的概率上升。

### 4.6 加密 DNS：本地 DoH 存根（`tools/doh_stub.py`）

只藏 SNI 不藏 DNS = 半个隐私。所以隐私模式会**默认自动**把系统 DNS 接管到本机存根：

```
应用 → 系统解析器(Dnscache) → 127.0.0.1:53（本地存根） --HTTPS 443--> 阿里/腾讯 DoH
                                                        （RFC 8484 wireformat 透传）
```

**关键实现选择**

- **上游用 IP 直连**（`https://223.5.5.5/dns-query`）：否则要解析 DoH 服务器自己的域名
  就得先用明文 DNS —— 引导问题。实测两种 IP 端点证书均有效。
- **RFC 8484 wireformat**：DNS 报文**原样透传**，不做解析/重建，
  因此 A / AAAA / HTTPS / SVCB / TXT / DNSSEC / EDNS 天然全兼容。
- **只绑 `127.0.0.1:53`**（不是 `0.0.0.0`）：不影响局域网，别的 DNS 服务照常。
- **显式禁代理** `ProxyHandler({})`：DNS 不该绕 HTTP 代理。
- **接管目标自动识别**：只碰「已连接 + 有 IPv4 DNS + 非虚拟网卡」的接口，
  实测本机 10 个网卡里精确命中 1 个（WLAN），虚拟网卡与未连接网卡全部排除。

**安全设计（改系统 DNS 是高危操作，复原优先于一切）**

1. 切换前先把原配置写进 `core/dns_backup.json`（已加进 `.gitignore`，含本机网卡信息）
2. **自检过了才动手**：存根必须真的通过 DoH 解析成功，才允许 `netsh` 改设置
3. 切离隐私模式 / 控制台退出时自动复原（`main()` 的 `finally`）
4. `restore_dns.cmd` 一键手动复原
5. 下次启动若发现有残留备份（上次异常退出），**先复原再干活**
6. 看门狗：每 15s 端到端自检，连续 3 次失败 → 自动复原并报错（网络可用性优先于隐私）
7. 没有管理员权限时只起存根、不改系统设置，并明确提示

**实测（2026-10-12，提权真机跑完整闭环，11/11 步通过）**

| 步骤 | 结果 |
|---|---|
| 识别接管目标 | WLAN = 172.20.10.1 (DHCP) ✅ |
| 存根启动 + DoH 全链路自检 | ✅ 180.101.49.44 / 180.101.51.73 |
| 接管后 `netsh` 显示 | WLAN → 127.0.0.1 ✅ |
| **接管期间系统解析** | `www.baidu.com → 183.2.172.177`（216ms，全程加密）✅ |
| 游戏域名 | `zzz.mihoyo.com → 140.249.108.26`（335ms）✅ |
| 复原 | WLAN 回到 172.20.10.1 ✅，备份删除 ✅，解析正常 ✅ |

**局限**

- 部分程序**硬编码自己的 DNS**（游戏客户端、某些代理工具）会绕过系统设置 —— 存根管不到
- 若 `127.0.0.1:53` 已被别的软件占用，存根起不来，会自动放弃接管（不会让 DNS 变死）
- DoH 上游全挂时看门狗会复原，但那一刻的隐私退回到"只有 SNI 被藏"

## 5. 明确不做的（Non-goals）

1. **不实现 DoH / DoT 代理。** 那是独立的一件事，混进来会让引擎职责不清。
   方案是**只做自检并提示**（P2）：检测当前解析器是否明文、是否被劫持。
2. **不伪造 / 篡改 ClientHello 内容。** 不改 SNI、不改扩展顺序 —— 那些会破坏 TLS 握手，
   且需要 MITM 证书，风险远大于收益。本方案只改**分段方式**。
3. **不做 IP 层伪装、不做 TTL 篡改、不做包乱序**。理由同上，且效果不确定。
4. **不自动切换 mode。** 不根据"检测到设备"来自动开隐私模式 —— 那会制造难以排查的行为。

## 6. 风险与代价（必须诚实说）

### 6.1 ⭐ 隐私模式可能让你**更**显眼

这是最反直觉、也最重要的一条。

现在（规则模式）：只有游戏流量被分片，网络上绝大多数流量是正常的。
开隐私模式后：**所有** TLS 都分片。

如果设备统计"分片连接占比"这类**宏观特征**，一个 **100% 分片**的终端非常突出。
换句话说：**隐私模式藏住了每一个单独的域名，却暴露了"这台机器在做规避"这个事实。**

随机切点能消除"固定偏移"这个微观签名，但**改变不了"分片率 100%"这个宏观特征**。

这不是说不该做，而是说：**不要以为开了它就更隐蔽。** 取舍要你自己判断。

### 6.2 合规

在校园网里主动规避上网行为管理设备，本身可能违反学校的网络使用协议。
这是事实陈述，不是劝阻 —— 但后果（比如账号被处置）需要使用者自己承担。

### 6.3 失效条件

- 设备升级为 **TCP 流重组** → 隐私模式与规则模式**一起失效**（本方案的根基就是"设备只看首包"）
- 设备改用 **DNS 侧封禁** → 分片无效，必须上 DoH/DoT
- 设备接入 **IP 归属库** → 识别到目标 IP 属于哪家服务，域名藏了也没用

| 全窗口扫描 | ⚠️ 对照组未 RST（**设备不在这条链路**）→ 结论无效，脚本已正确标记 |

## 8. 验收标准

**单元测试**（不需要管理员 / 驱动，Linux 也能跑）

1. privacy 模式下 `split_packet()` 返回的 `domain is None`
2. privacy 模式下 `info` 字符串**不含任何域名**（正则断言不含 `.com` / `.net` / `.org` 等）
3. privacy 模式对**非规则域名**也分片（用 `www.some-private-site.com` 断言段数 = 2）
4. `off` 模式下 privacy 相关逻辑不生效（回归）
5. 随机切点：跑 1000 次，断言 `cut ∈ [max(min_cut,114), host_start-1]`
6. `host_start < 125` 时窗口为空 → 回退固定切点且不抛异常
7. 多端口 filter 字符串生成正确（`tcp.DstPort == 443 or tcp.DstPort == 8443`）
8. 原有 53 个单测全部通过

**端到端**

- 浏览器访问一个**不在任何规则里**的站点，事件日志面板里**看不到该域名**
- `core/fragconfig.json` 中不含任何被访问域名
- ⚠️ **抓包验证做不了**：当前链路已经没有那台行为管理设备（见 `research/README.md`），
  无法在真实设备上验证"首段确实不含 SNI"。
  只能退而用 `tools/fragdpi.py --packettest` 验证分片算法本身正确。

## 9. 决策记录

| # | 问题 | 结论 |
|---|---|---|
| 1 | privacy 模式下规则表要不要清空？ | **保留但忽略** —— 切回规则模式时不用重建规则 |
| 2 | 端口集默认值？ | 默认 `[443]`，用户可自行加 `8443,2053` 等 |
| 3 | 随机切点默认开还是关？ | **默认关** —— §4.4 的「窗口内每个 cut 都放行」尚未实测验证 |
| 4 | 退出时自动清日志默认开还是关？ | **默认开** —— 符合隐私模式语义（代价是不好查历史问题） |
| 5 | README 是否公开 §6.1「可能更显眼」的警告？ | **公开** —— 只讲好处不讲代价的隐私功能不诚实 |
| 6 | 加密 DNS 是否默认随隐私模式启用？ | **用户指定：默认启用**（这正是"完整隐私"的另一半）。见 §4.6 |
| 7 | DoH 上游用域名还是 IP？ | **IP 直连** —— 避免「解析 DoH 域名要先明文 DNS」的引导问题 |
| 8 | 改动系统 DNS 的失败处理？ | 网络可用性优先：连续 3 次自检失败 → 自动复原 |
